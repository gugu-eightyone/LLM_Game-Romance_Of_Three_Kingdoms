# LLM 삼국지 전략 시뮬레이션

위·촉·오 세 나라를 각각 LLM 에이전트가 군주로서 운영하는 턴제 전략 게임입니다. 사람도 한 나라를 맡아 LLM 세력과 겨룰 수 있습니다.

게임 규칙은 코드가 판정하고, LLM은 명령과 전략만 정하도록 역할을 나눴습니다. LLM이 규칙에 어긋난 명령을 내리면 실행하지 않고 횟수를 기록해, 그 기록을 보며 프롬프트와 게임 규칙을 고쳐 왔습니다.

## 게임 개요

| 항목 | 내용 |
|---|---|
| 세력 | 위·촉·오 3개 세력, 도시 16개, 장수 39명 |
| 진행 | 1턴 = 1개월. 세 세력이 동시에 명령을 내리고 한꺼번에 처리 |
| 명령 | 출격(공성·야전), 내정(식량 증산·모병·사기 진작·성벽 보수), 호송, 장수 이동, 작전 지시(전략 변경·회군), 외교(동맹·파기·포로 반환·항복 권유), 포로 설득·처분 |
| 승리 조건 | 모든 도시를 한 세력이 차지 |
| 플레이 | Streamlit 화면에서 한 세력을 직접 운영하거나, 관전 모드로 세 세력 모두 LLM에 맡겨 진행 |

<br>

## 기술 스택

`Python 3.12` `OpenAI SDK` `Pydantic` `Streamlit` `pytest`

- 모델: `gpt-5.4-mini` (6가지 모델 설정을 비교해 선택)
- LangGraph·LangChain은 첫 버전에서 썼다가 제거했습니다.

## LLM과 규칙 엔진의 역할 분리

| 코드(게임 엔진)가 처리 | LLM이 처리 |
|---|---|
| 이동, 전투, 도시 점령, 자원 계산, 승패 | 어느 도시를 몇 명으로 공격할지 같은 명령과 전략 설명 |
| 명령이 규칙에 맞는지 검사하고, 어긋나면 실행하지 않고 횟수를 기록 | 외교 제안에 대한 응답, 포로와의 대화 |
| 심판에게 계산된 사실(목표 도시 소유, 수비 병력, 거리) 제공 | 전략의 구체성과 상성을 채점하는 심판 (전투력을 소폭 보정) |

- 전투 판정에 쓰는 난수는 시드로 고정하고, LLM은 숫자를 바꿀 수 없습니다.
- LLM 출력은 Pydantic 스키마로 받습니다. 형식이 어긋나면 한 번 재시도하고, 그래도 실패하면 아무 효과 없는 기본 명령으로 처리합니다. 모델 비교 중 24번 연속 실패가 났을 때도 앱은 멈추지 않았습니다. (그동안 세 세력은 아무 행동도 하지 못했습니다.)
- 규칙 위반을 기록하도록 만들자, LLM을 처음 연결한 날 엔진 버그 2개가 드러났습니다. 자기 도시를 공격하는 명령을 엔진이 그대로 받아 주는 등, 직접 만든 테스트 시나리오에서는 보이지 않던 문제였습니다.

## 개선 과정

### 1. 자국 도시 공격 오류 9회 → 0회

4턴 테스트에서 에이전트가 자기 나라 도시를 공격하는 명령이 9번 나왔습니다. 금지 문구를 추가하기보다, 어떤 상황에서 이 명령을 골랐는지 먼저 확인했습니다.

| 단계 | 변경 | 오류 |
|---|---|:---:|
| 처음 | — | 9 |
| 1차 | 주변 도시마다 소유 세력과 가능한 행동 표시 | 3 |
| 2차 | 가능한 행동을 모두 보여주고, 출격 목적(구원·요격) 구분 | 1 |
| 3~4차 | 기능 추가 후 다시 증가 | 6 |
| 5차 | 구원군이 목적지에 남도록 규칙 변경 | 1 |
| 이후 | 모델 교체 후에도 유지 | 0 |

- 1차 개선 후 남은 3건은 모두 공격받는 아군 도시를 도우려는 경우였습니다. 아군 도시에 할 수 있는 행동이 '병력 이동'으로만 표현돼 구원을 선택지로 떠올리지 못한다고 보고, 쓸 수 있는 행동을 모두 보여주도록 바꿨습니다.
- 다시 6회로 늘었을 때도 모두 방어하려는 의도였습니다. 로그를 따라가 보니 제가 만든 규칙이 원인이었습니다. 구원군이 적보다 먼저 도착하면 원래 도시로 돌아가 버렸고, 혼자 남은 도시를 지키려고 에이전트가 공격 명령을 쓴 것으로 보였습니다.

> 조건마다 4턴 테스트를 1회씩 돌린 결과이고, 다시 늘어난 구간에는 temperature 변경도 함께 있었습니다. 구원군 복귀가 원인이라는 판단은 로그를 근거로 한 추정입니다.

### 2. LLM 심판 검증

게임에는 정해진 정답이 없어서, 평가를 형식 오류, 규칙 위반, 판단 품질, 밸런스, 심판 정확도, 비용의 6가지로 나누고 정답이 있는 항목부터 측정했습니다.

직접 플레이해 보니 심판이 장수 이름만 나열한 전략에는 점수를 더 주고, 규칙상 유효한 협공에는 점수를 깎았습니다. 잘못된 판정 20건을 모아 기대 판정을 직접 붙였습니다.

- **수정**: 채점할 때 엔진이 계산한 사실(목표 도시 소유, 수비 병력, 거리)을 함께 넘기고, 사실을 우선하도록 채점 기준에 명시했습니다. 했던 말을 반복한 문장은 점수에 반영하지 않도록 기준도 고쳤습니다.
- **결과**: 같은 입력을 실제 API로 다시 채점해, 기대 판정과 일치한 사례가 12건 중 2건에서 11건으로 늘었습니다.
- **한계**: 수정에 참고한 사례로 다시 잰 결과라 일반적인 정확도로 볼 수 없습니다. 수정한 날 오후 플레이에서 같은 유형의 오판이 다시 나왔고, 같은 문장을 6번 채점하면 1번은 다른 점수가 나왔습니다.

### 3. 모델 선택

같은 4턴 자동 대전으로 6가지 모델 설정(gpt-4.1-mini 온도 2종, 5.4-mini, 5.4-nano, 5-mini, 5-nano)을 비교하고, 명령 오류, 새 명령 사용 여부, 지연 시간, 단가를 정리했습니다.

- 5-mini·5-nano는 호출당 17초 이상 걸려 제외했습니다.
- 5.4-nano는 안내 문구를 명령 필드에 그대로 베끼는 오류가 18건 나왔습니다.
- 새 명령을 가장 잘 쓰고 지연이 가장 짧은(호출당 2.7초) **gpt-5.4-mini**를 선택했습니다. 단가가 4.1-mini의 약 2.8배인 점은 단점입니다.

모델당 1회 실행이라 1차 선별 수준의 비교입니다.

### 4. LangGraph·LangChain 제거

첫 버전은 LangGraph로 세 세력 판단과 심판을 연결했습니다. 재설계하면서 실제로 쓰는 기능을 확인해 보니, 반복 흐름이나 상태 저장 기능은 쓰지 않았고 게임 상태는 Streamlit 세션에 따로 저장하고 있었습니다. 구조화 출력도 OpenAI SDK만으로 받을 수 있어 둘 다 제거했습니다.

## 프로젝트 구조

```
app.py              # Streamlit 앱 (플레이 화면)
src/
├─ engine.py        # 게임 엔진: 턴 진행, 전투, 경제, 외교, 명령 검사
├─ decide.py        # 세력별 LLM 판단, 심판 채점
├─ parley.py        # 포로 대화·설득
├─ llm.py           # OpenAI 호출, 구조화 출력, 재시도·기본값 처리
├─ models.py        # 게임 상태·명령 Pydantic 모델
├─ prompts.py       # 프롬프트 조립
└─ config.py        # 게임 수치 설정
prompts/            # 판단·심판·대화 프롬프트 원문
data/               # 시나리오(세력·도시·장수), 지도
tests/              # pytest (API 키 없이 실행)
prototype/          # 개인 과제로 만든 첫 버전 (비교용으로 보존)
```

## 실행 방법

```bash
pip install -r requirements.txt
```

저장소 루트에 `.env` 파일을 만들고 `OPENAI_API_KEY`를 넣습니다. (`.env.example` 참고)

```bash
# 게임 실행
streamlit run app.py

# 세 세력 모두 LLM으로 자동 진행 (인자 = 턴 수, 실제 API 호출 비용 발생)
python -m src.decide 6

# 테스트 (API 키 불필요)
pytest
```
